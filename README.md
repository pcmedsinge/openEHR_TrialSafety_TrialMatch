# Clinical Trial Intelligence Suite

Two AI-powered web apps built on OpenEHR / EHRbase — a live Clinical Data Repository implementing the global OpenEHR standard used in national health systems across Norway, Slovenia, and parts of the NHS.

---

## Apps

### Signal Monitor — Pharmacovigilance Dashboard

Connects to EHRbase and gives trial safety teams a real-time view of:

- Adverse event frequency by type and severity across all participants
- Grade 2+ safety signal detection within any configurable date window
- Individual participant timelines — AEs, blood pressure, pulse, temperature across every visit
- One-click **ICH E2B safety narrative** generated by GPT-4o with live streaming output

### Eligibility Screener — Trial Recruitment Tool

- Paste free-text eligibility criteria from any trial protocol
- GPT-4o extracts structured inclusion/exclusion criteria and generates a live AQL query
- Review and edit both criteria and query in the UI before running
- Match results with a streaming AI narrative explaining who qualifies and why

## Architecture

```
localhost:3000  (http-proxy)
  /match/*  →  Eligibility Screener  (Vite :5174)
  /*        →  Signal Monitor        (Vite :5173)

EHRbase CDR  →  localhost:8080  (Docker)
PostgreSQL   →  localhost:5432  (Docker)
```

Both apps query EHRbase directly using **AQL (Archetype Query Language)**. All AI features use **OpenAI GPT-4o** with streaming.

## Getting Started

### 1. Prerequisites

- Docker Desktop running
- Node.js 18+
- OpenAI API key

### 2. Start EHRbase

```powershell
.\start.ps1
```

This starts EHRbase + PostgreSQL via Docker Compose and installs proxy/frontend dependencies.

### 3. Seed the database

```powershell
cd seed
npm install
npx ts-node seed.ts
```

Seeds 30 fictional trial participants with demographics, ADHD/autism screening scores, 150+ clinical visits with vitals, and a deliberate safety signal at Week 8 (co-occurring Moderate Fatigue and Headache in 4 participants).

### 4. Configure environment variables

Copy `.env.example` to `.env` in both frontend directories and fill in your values:

```
VITE_OPENAI_API_KEY=sk-proj-...
VITE_EHRBASE_URL=http://localhost:8080/ehrbase/rest/openehr/v1
VITE_EHRBASE_USER=ehrbase-user
VITE_EHRBASE_PASS=SuperSecretPassword1234
```

### 5. Open the app

Navigate to `http://localhost:3000`

### Stop

```powershell
.\stop.ps1
```

## Key Technical Notes

**AQL path systems** — OpenEHR uses two different path systems. The FLAT API (used for writing data) uses template-relative paths like `blood_pressure/any_event:0/systolic|magnitude`. AQL (used for querying) uses archetype at-codes like `v/data[at0001]/events[at0006]/data[at0003]/items[at0004]/value/magnitude`. There is no automatic mapping between them.

**EHRbase AQL constraints** — Multi-archetype joins through the same composition variable fail silently. `SELECT DISTINCT` with column aliases is rejected. Always use separate queries per archetype and full paths in `ORDER BY`.

**GPT-4o AQL generation** — The model is constrained to four proven query templates. Unrestricted generation produces syntactically plausible but semantically broken AQL that EHRbase silently discards.
